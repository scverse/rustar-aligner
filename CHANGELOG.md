## [Unreleased]

### Other changes

- Third-party notices completed. `LICENSES/` gains the licences of code
  ported from DegNorm (MIT) and David Elworthy's `sgt.h` via STAR (BSD
  2-clause), and of libc++ (Apache 2.0 with LLVM Exceptions), whose random
  number behaviour `libcxx_rng.rs` reimplements; the files name them; `src/solo/sgt.rs` carries Elworthy's full notice, as his
  licence requires of source copies. The release archives and the Docker
  image now include `LICENSES/` (and the image `LICENSE`), since the notices
  of STAR and the others are required in binary distributions too. The
  crate's declared licence is now `MIT AND BSD-2-Clause`, since
  `src/solo/sgt.rs` is a port of BSD 2-clause code.

  The release archives and the Docker image also ship
  `THIRD_PARTY_LICENSES.md`, the licence notices of every crate linked into
  the binary (including the C libraries libdeflate and mimalloc that two of
  them compile in), generated by `scripts/third-party-licenses.sh` with a
  pinned, checksum-verified `cargo-about`. Only permissive licences are
  accepted (`about.toml`); a CI job runs the same generation, so a
  dependency under any other licence, or a changed licence file, fails on
  the pull request that brings it in.

- ruzstd 0.9.0 → 0.9.1 for RUSTSEC-2026-0344 (a small zstd input could
  exhaust memory). Only builds with the optional `zstd` or
  `compressed-input` feature contain ruzstd; the default build does not.

- noodles 0.113 → 0.116 and noodles-bgzf 0.49 → 0.51, bumped together. The
  direct `noodles-bgzf` dependency exists only to enable its `libdeflate`
  feature; bumping one without the other puts two copies in the tree, and
  noodles then writes BAM through the copy without libdeflate. BAM output is
  byte-identical before and after. (0.117 needs Rust 1.91, above the 1.89 MSRV.)

- Production genome indexing now enables caps-sa 0.7's bounded geometric LCP
  memoization through its stable policy API. On the complete ruSTAR-shaped
  GRCh38 plus GENCODE v50 fixture (6.56 billion symbols, 6.18 billion retained
  suffixes, 1.40 million segments, 32 physical cores), the final caps-sa 0.7
  implementation built the SA in 172.953 s versus 267.592 s for its original
  0.7 baseline: 35.4% faster, with peak RSS reduced from 10,512,408 to
  9,169,892 KiB. The complete output hash was unchanged.

- The splice-junction sorts that produce `SJ.out.tab`, the `SJ` solo-feature
  rows and the `BySJout` survivor set now order on the whole key (chromosome,
  start, end, strand, motif) rather than on coordinates alone. The counts come
  from a `DashMap`, whose iteration order varies with hashing and with
  concurrent insertion, so a tie left to that order would have been a file
  that differs between runs or thread counts. `tests/determinism.rs` locks it:
  the same reads at one and at eight threads, and two runs at eight threads,
  produce byte-identical output in single-pass and two-pass mode. Answers #210.

- `cluster_seeds` reuses its window-bin map across reads on a thread instead
  of rebuilding it per read. Merging two windows re-keys every bin in the
  merged span, so the per-read pre-sizing was only a floor and the map
  rehashed; profiling a human 10x run put that rehash at 2.1% of on-CPU time.
  Output-neutral, verified by an empty diff on 20 M read pairs.

### Features

- **`--clipAdapterType CellRanger4` now matches STAR exactly**, both halves of the
  clip (#198). The 5' TSO trim is an overlap alignment against the first 91 bases of the
  read, replicating `ClipCR4`'s Opal call (ACGTN alphabet; match +1, mismatch -2,
  any-vs-N -2, N-vs-N 0; gap open = gap extend = 2; overlap mode with end
  tracking), followed by STAR's acceptance gate
  `S<20 || (S==20 && L>26) || (S==21 && L>30)`. The 3' trim is STAR's scored
  `polyTail3p` scan, replacing a "trailing run of A >= 8" approximation that was
  wrong in both directions (a read ending in 10 A's was trimmed by 10 where STAR
  trims 0; `A*15 + C + A*15` was trimmed by 15 where STAR trims 31). The poly-A
  transcription is taken from Benjamin Demaille's #148 and moved onto the solo
  path, which is where `CellRanger4` is actually reached; #148's `clip_mate`
  wiring is not used and that PR is superseded.

  The overlap alignment comes from [`hyalite`](https://crates.io/crates/hyalite)
  0.4.0 (pinned exactly) — a new dependency, pure Rust with no dependencies of
  its own. Reads are
  scanned a batch at a time via `Database::scan_all`, mirroring STAR's
  `ClipMate::clipChunk`, which aligns the adapter against a chunk of reads in one
  Opal call.

  Both halves are gated against STAR's own C++: `tests/data/cr4_opal_oracle.cpp`
  links STAR's `opal.cpp` and reproduces `ClipCR4` + `ClipMate::clipChunk`
  verbatim, and the committed `cr4_opal_oracle.tsv` is its output over 938 reads
  chosen to straddle both decision boundaries. `cr4_tso_matches_star_opal_oracle`
  checks every one against the scalar path, a forced-SIMD path, and the
  production batch path.

  Measured on 10x mouse chr19 with both tools under `--clipAdapterType
  CellRanger4`: clip-amount differences against STARsolo drop from 154 to **0**,
  and the soft-clipped share moves from 39% (STAR 41%) to 34.9% (STAR 35.0%).
  Default SE/PE alignment is untouched, as `CellRanger4` is opt-in: SE 8788/8926
  and PE 8390 both-mapped / 0 half-mapped, both unchanged.

  The clips run in STAR's `ClipMate::clip` order (`clip::clip_mate_cr4`): fixed
  5' bases, then the TSO (found on the original read, capped at what is left),
  then on the 3' end the fixed bases and then `polyTail3p`. `CellRanger4` now
  also applies outside STARsolo, as in STAR; it was ignored there. As STAR, it
  is refused with two mates and with `--clip3pAdapterSeq`, and
  `--clipAdapterType` takes only `Hamming` or `CellRanger4` (`None` was
  accepted). Plain single-end alignment of the fixture's cDNA reads with
  `CellRanger4`: 21,732/21,732 records identical to STAR.

  With a non-zero `--clip5pNbases`, STAR counts the fixed 5' bases as
  clipped without removing them, so its records place SEQ `clip5pNbases`
  away from the bases it aligned (its own `nM` matches the record only
  after that shift). rustar-aligner removes them and its records describe
  the alignment made; see DIVERGENCE.md §1.7.
- **Bulk total RNA-seq: unspliced targets, splicing-status tag and
  spliced / unspliced gene counts** (rustar-aligner extensions, opt-in, see
  DIVERGENCE.md §1.4 and the "Bulk total RNA-seq" guide; from
  @BenjaminDEMAILLE's #283).
  - `--quantTranscriptomeUnspliced Intron|PreMRNA` adds one `<gene_id>-I`
    target per gene (merged introns plus `--quantTranscriptomeUnsplicedFlank`,
    or the gene body) after the transcripts of
    `Aligned.toTranscriptome.out.bam`; unspliced reads are projected onto
    every compatible target, spliced and unspliced, so a read in a retained
    intron is no longer forced onto the retained-intron isoform. Writes
    `Aligned.toTranscriptome.targets.tsv` and, on request, the unspliced
    sequences (`--quantTranscriptomeUnsplicedFasta Yes`).
  - `--outSAMsplicingStatus Yes` tags genomic alignments `sp:A:S|U|A`
    (spliced / unspliced / ambiguous).
  - `--quantGeneSplicing Yes` writes `ReadsPerGeneSplicing.out.tab` and
    `ReadsPerGeneSplicing.summary.tsv`, using STARsolo's spliced / unspliced
    classification on each read or pair.
  - These are separate rustar-aligner flags, not new values of STAR's
    `--quantMode` or `--outSAMattributes`, so a STAR command line keeps its
    STAR meaning.
  - `--quantGeneSplicing Yes`, `--outSAMsplicingStatus Yes` and
    `--quantTranscriptomeUnspliced` need transcript tables at mapping: an
    index built with a GTF, or `--sjdbGTFfile` at mapping.
- `--sjdbGTFfile` accepts a gzipped GTF, detected by its first bytes, at
  `genomeGenerate`, at mapping and in `--runMode liftOver` (from
  @BenjaminDEMAILLE's #319). STAR reads plain text only (DIVERGENCE.md §4.4);
  plain-text GTFs are read as before, and the outputs are the same either way.
- **DegNorm degradation normalization** (rustar-aligner extension, no STAR
  counterpart, from @BenjaminDEMAILLE's #232; DIVERGENCE.md §1.5).
  `--quantGeneCoverage Yes` records per-gene, per-exonic-base coverage during
  alignment and writes `GeneCoverage.out.bin`; `--degNormCoverageFiles`
  merges two or more samples' coverage files through a port of DegNorm's
  rank-one NMF over-approximation and writes `DegNorm.out/` with
  `DegradationIndex.tab`, `AdjustedCounts.tab`, `RawCounts.tab`,
  `ScaleFactors.tab` and `Summary.txt`. Parameters: `--degNormIter`,
  `--degNormNmfIter`, `--degNormDownsampleRate`, `--degNormMinimaxCoverage`,
  `--degNormSkipBaselineSelection`, `--degNormBins`,
  `--degNormMinHighCoverage`, `--degNormSampleId`. Off by default; alignment
  output is unchanged.
- **FASTQ compression is detected by content, and bzip2 / zstd / xz input is
  available behind features** (from @BenjaminDEMAILLE's #272, #218;
  DIVERGENCE.md §4.5). `--readFilesIn` is sniffed by magic bytes
  instead of by the `.gz` / `.gzip` extension, so a gzip file with any name is
  decoded and a plain file named `*.gz` is read as plain. gzip decoding is
  multi-member aware. New optional Cargo features, all pure Rust, none in the
  default build: `bz2` (`bzip2` with its `libbz2-rs-sys` backend), `zstd`
  (`ruzstd`, multi-frame and skippable-frame aware), `xz` (`lzma-rust2`,
  multi-stream), and `compressed-input` for all three. A build without the
  matching feature stops with an error naming the feature and the
  `--readFilesCommand` alternative. `--readFilesCommand` still takes
  precedence.
- **STARsolo SAM tags and `CB_samTagOut`, as STAR** (from
  @BenjaminDEMAILLE's #226). `--outSAMattributes` now takes
  `CR CY UR UY CB UB gx gn sM sS sQ sF` next to `GX GN`, written in BAM output
  only and in the order given.

  - The gene tags come from the first `--soloFeatures` entry, STAR's
    `samAttrFeature`: `classifyAlign`'s per-alignment gene sets for `Gene`,
    gene-body overlap for `GeneFull` (`ReadAlign_alignBAM.cpp:99-106,
    420-452`). `gx`/`gn` name every gene of their alignment; `sF` is
    `(ovType, genes of the read)`, which for `Gene` is 1 when the read has a
    gene and 0 otherwise, and always 0 for `GeneFull`.
  - `CB`/`UB` come from STAR's readInfo and are written in the
    coordinate-sorted BAM only. Counted reads get their cell and corrected
    UMI. Reads with a valid barcode that are not counted (unmapped, no gene,
    several genes) get the cell their barcode resolves to and the raw UMI, as
    STAR's no-feature records give them; reads with no valid barcode get `-`.
  - On unmapped records the barcode tags follow STAR's fixed order.
  - `--soloType CB_samTagOut` corrects the barcode into `CB` as each read is
    processed, with no counting and no matrices.
  - The refusals are STAR's, in STAR's order and with STAR's text: the
    barcode tags without BAM output, `CB`/`UB` without a sorted BAM or with a
    non-gene first feature, `UB` with `CB_samTagOut`, and `CB_samTagOut`
    with a match type other than `Exact`/`1MM` (so its `1MM_multi` default
    is refused, as in STAR) or with multimappers. `gx`, `gn` and `sF` with SAM
    output are refused too: STAR has no check for them but stops at the first
    SAM record.

  On the 10x v2 mouse chr19 fixture, every tag matches STARsolo on all
  104,045 records of the sorted BAM, unmapped reads included and in record
  order. That holds for the default run, for a scrambled tag order with both
  BAM outputs, for `GeneFull` first, `1MM_multi` with EM multimappers,
  `1MM_Directional`, `Unstranded` and `CB_samTagOut`, and the matrices are
  unchanged.

- **Paired-end cDNA with a separate barcode read.** `--readFilesIn` takes
  STAR's three-file solo layout (`cDNA_read1 cDNA_read2 barcode_read`); a
  third file without `--soloType` is refused with STAR's message. A mate pair
  is one alignment for the Gene feature, as in STAR: one transcript has to
  contain both mates. This also applies to `--soloBarcodeMate 1`, which
  scored each mate as an alignment of its own.

- **`--soloBarcodeReadLength` is honoured.** As in STAR, the default expects the
  barcode read to be exactly CB+UMI long and treats any other length as a fatal
  input error; `0` turns the check off and pads a short read with `N`
  (quality `H`).

- **CLI and output parity: SAM/SJ/read-input knobs and the STAR limit
  surface** — 30 further STAR 2.7.11b parameters. (`--outSAMorder` came from #145.)

  - Implemented: `--outSAMmode` (`Full`/`NoQS`/`None`), `--outSJtype None`,
    `--outSJfilterReads Unique`, `--outSAMheaderHD`, `--outSAMheaderPG`,
    `--outSAMheaderCommentFile`, `--readFilesPrefix`, `--readNameSeparator`,
    `--readQualityScoreBase`, `--outQSconversionAdd`.
  - Refused loudly rather than accepted and ignored:
    `--outSAMfilter KeepOnlyAddedReferences` / `KeepAllAddedReferences` and
    `--readFilesType SAM`, both of which need machinery this aligner does not
    have.
  - Accepted and documented as output-neutral: the `--limit*` family,
    `--outTmpDir`, `--outTmpKeep`, `--runDirPerm`, `--genomeFileSizes`,
    `--outBAMsorting*`, `--readMatesLengthsIn`.

  `tests/parameter_surface.rs` now checks every STAR 2.7.11b parameter name
  against the CLI, so the coverage figure is machine-checked and surface drift
  fails a test.

### Bug fixes

- **STARsolo's stats files as STAR writes them.** `Solo.out/Barcodes.stats`,
  `<feature>/Features.stats` and `<feature>/UMIperCellSorted.txt` were not
  written, SJ and Velocyto had no `Summary.csv`, and the Gene/GeneFull
  `Summary.csv` lacked the Q30 and "Unique+Multiple" lines, printed fixed
  decimals, and computed several values its own way. They now come from
  STAR's counters (`SoloReadBarcodeStats`, `SoloReadFeatureStats`) and its
  `statsOutput`:
  - each read counts once in `Barcodes.stats`, under its final `cbMatch`
    code (a UMI rejection replaces the barcode's); a missing adapter or UMI
    is counted as STAR counts it;
  - the per-feature counts come from STAR's three stages: per read
    (`record`), at counting (oneExact and 1MM_multi rejections) and at UMI
    collapse; Velocyto keeps only the UMIs and cells, as `countVelocyto`
    never sums the rest;
  - "Reads With Valid Barcodes" subtracts both barcode and feature
    rejections; "Reads Mapped to <feature>: Unique" is the counted reads;
    means are integer, medians the element at `nCells/2`, the UMI median
    from every barcode's UMIs;
  - doubles, here and in `UniqueAndMult-*.mtx` (which printed `0.50000`
    for STAR's `0.5`), are written as C++'s `ostream` does;
  - `CB_samTagOut` writes `Barcodes.stats`, and so does a run with
    `--soloCBwhitelist None` (all zeros, as STAR's: it bins reads only
    against a whitelist). That mode still writes no matrices.

  Also: a barcode's exact-match count (used by oneExact and the 1MM_multi
  posterior) now counts only reads whose UMI passed too, as STAR's
  `addStats` does; it counted exact barcodes with a rejected UMI. Across 30
  STARsolo configurations of the 10x v2 mouse chr19 fixture, 453 of 457
  `Solo.out` files are byte-identical to STARsolo's; the other four are the
  `CB_UMI_Complex` homopolymer UMIs of DIVERGENCE.md §1.6.

  STAR's per-line SJ counts are ported too: a junction that is not a matrix
  row counts nowhere, a read with no junction is `noNoFeature` (a
  1MM_multi barcode with junctions was too), and 1MM_multi barcodes on SJ
  records, which were dropped, are resolved by the posterior as for Gene. `CB_UMI_Complex` reads rejected
  twice can land in a different `Barcodes.stats` bin from STAR's
  (DIVERGENCE.md §3.4).

  `CellRanger.summary.csv`, a rustar-aligner extension written whenever
  Gene and GeneFull both ran, is now opt-in: `--soloCellRangerSummary Yes`
  (DIVERGENCE.md §1.8). By default `Solo.out` holds only STARsolo's files.

- **`--soloCellFilter TopCells N` calls cells as STARsolo.** It took the N
  barcodes with the most UMIs. STAR keeps every barcode with at least the
  UMIs of the barcode at index N of the descending list, the (N+1)th, so
  ties are kept (`SoloFeature_cellFiltering.cpp:46-59`). With `TopCells 100`
  on the 10x v2 mouse chr19 fixture STAR calls 106 cells and rustar-aligner
  called 100; the filtered matrices are now identical.

- **`--soloFeatures Velocyto` counts as STARsolo.** It used its own rule (a
  junction means spliced, an intronic block unspliced, anything else
  ambiguous), read by read. It now ports STAR's:
  - each uniquely mapped read is compared with every transcript that
    contains it on the `--soloStrand` strand (`alignToTranscriptMinOverlap`,
    velocyto's 5-base flank, already ported for bulk use in
    `quant/splice_status.rs`);
  - a molecule (cell, UMI, taken from the Gene feature's readInfo) keeps the
    transcripts all its reads share; it is spliced, unspliced or ambiguous by
    STAR's model flags, and dropped if its transcripts span two genes
    (`SoloFeature_countVelocyto.cpp`);
  - all three matrices hold the same (cell, gene) rows, zeros included;
  - `Velocyto/filtered/` is written, for the Gene feature's called cells that
    Velocyto detected (`SoloFeature_cellFiltering.cpp:16-30`), unless there
    are none (`:106-108`).

  On the 10x v2 mouse chr19 fixture the raw and filtered matrices are now
  byte-identical to STARsolo's (spliced/unspliced/ambiguous UMIs 369/57/32,
  against 52/100/362 before), in 10 configurations: Unstranded, Reverse,
  `1MM_multi`, GeneFull listed first, with `CB`/`UB` tags, `1MM_Directional`
  and `Exact` dedup, EmptyDrops_CR, and paired-end cDNA. STAR keeps a readInfo
  per feature (`CB`/`UB` read the first feature's, Velocyto the Gene
  feature's), and so does rustar-aligner now. `--soloFeatures Velocyto`
  without `Gene`, on which STAR crashes, is refused; with `--soloType
  SmartSeq` it is refused with STAR's message.

  `--soloVelocytoAmbiguous` is removed. It was a rustar-aligner extension
  that folded ambiguous molecules into spliced, on the premise that exon-only
  reads land in ambiguous; under STAR's model they are spliced, and ambiguous
  means exonic in one isoform and intronic in another.

- **Paired-end reads with mates of 50 bases or fewer align as STAR.** STAR
  caps the spacing of its seed search starts by the whole read, both mates
  and the spacer (`ReadAlign_mapOneRead.cpp:41-42`); we capped each mate by
  its own length, so a mate of 50 bases or fewer got a second search start
  that STAR never makes, and with it seeds that paired mates STAR leaves
  unpaired (any mate length is affected with a non-default
  `--seedSearchStartLmaxOverLread`). Separately, the primary among equal-scoring pairs is now STAR's
  `trBest` length tie-break over the pair's span in transcript order
  (`stitchWindowAligns.cpp:94`), not over the mates' extent; the two differ
  when the mates overlap. On 100,000 45+45 pairs made from the 10x mouse
  chr19 fixture's cDNA reads, every one of 207,966 records now matches STAR
  (65,144 before; we mapped 16,033 pairs to STAR's 14,590). Yeast 10k SE/PE
  and the human chr21 clean pairs (75-base mates) are unchanged and
  identical to STAR.

- **Several read files per mate, as STAR** (from @BenjaminDEMAILLE's #318).
  `--readFilesIn a_1.fq,b_1.fq a_2.fq,b_2.fq` (e.g. 10x lanes) failed with
  "No such file or directory": the comma list was taken as one path. Each
  entry is now split on commas, `--readFilesPrefix` is prepended to every file
  by plain concatenation (it was joined as a directory), and the files of a
  mate are read in order (`Parameters_readFilesInit.cpp`). With one
  `--outSAMattrRGline` entry per file, each read gets its file's read group,
  in the genomic and transcriptome BAMs. A different file count per mate, or
  an RG count other than 1 or the file count, stops with STAR's message.
- **The gene model comes from the index tables when no `--sjdbGTFfile` is
  given at mapping** (from @BenjaminDEMAILLE's #308). STAR reads
  `geneInfo.tab` and the transcript tables from `--genomeDir`
  (`Transcriptome.cpp:13-18`) and only stops when they are missing;
  rustar-aligner required `--sjdbGTFfile` for `--quantMode GeneCounts` and
  STARsolo `Gene`/`GeneFull`/`Velocyto` even on an index built with a GTF. On
  the yeast 10k reads with the annotated index and no GTF, `ReadsPerGene.out.tab`
  is identical to STAR's, SE and PE. With no annotation at all the run stops
  with STAR's "could not open ... geneInfo.tab" message.
- **A GTF given at mapping gives STAR's transcript order** (from #313).
  Transcripts are sorted by start, then end, then GTF order
  (`GTF_transcriptGeneSJ.cpp`), as in `transcriptInfo.tab`, so the
  transcriptome BAM's `@SQ` lines now match STAR's; they were in GTF order.
  `exonGeTrInfo.tab` in `<prefix>_STARgenome/` keeps STAR's GTF-order
  transcript numbers (#313 as submitted wrote the sorted ones).
- **SAM/BAM records and headers match STAR's** (from @BenjaminDEMAILLE's #306,
  #309, #310, #314, #297 and #305). On the yeast 10k reads, SE and PE, every
  record and every header line other than the two that name the program
  (DIVERGENCE.md §3.3) is now identical to STAR's in all the configurations
  tried: default, `--outSAMunmapped Within` (and `KeepPairs`), a custom
  `--outSAMattributes` order, `All` in BAM, `intronMotif`, an explicit `XS`,
  read groups, `--chimOutType WithinBAM`, both BAM outputs, and user `@HD`,
  `@PG` and comment-file headers. Default records were already identical; the
  default header changes from `@HD VN:1.6` to STAR's `VN:1.4`.
  - Optional tags are written in `--outSAMattributes` order, then RG, XS, vW,
    then NM for WithinBAM (`Parameters_samAttributes.cpp`, `STAR.cpp:188`);
    tags outside the list, such as `SA`, follow them. Unmapped records always
    carry `NH HI AS nM uT` then `RG`, and the transcriptome BAM `NH HI` then
    `RG`. Unspliced alignments get `jM:B:c,-1` and `jI:B:i,-1`. (#306)
  - `MC` (mate CIGAR) and `ch` (WithinBAM chimeric records) are accepted, and
    `All` is STAR's `NH HI AS nM NM MD jM jI MC ch`. (#309)
  - Unmapped records take `AS` and `nM` from STAR's best transcript, MAPQ 0,
    `uT:A:4` for the unmapped mate of a half-mapped pair, and STAR's mate
    fields. (#310)
  - `XS` in `--outSAMattributes` turns on `--outSAMstrandField intronMotif`,
    as in STAR, instead of being dropped; a pair's XS comes from both mates'
    junctions, with the annotated strand for sjdb junctions. (#314)
  - The header follows STAR's layout and text (`samHeaders.cpp`), including
    the transcriptome BAM's `@SQ`/`@RG`-only header. (#297)
  - `--outSAMtype BAM Unsorted SortedByCoordinate` writes both files, and
    `--outStd` sends only the matching output to stdout. (#305)
- `NM:i` counts a base where the read or the genome is N as a mismatch, as
  STAR's `samAttrNM_MD` does (`ReadAlign_alignBAM.cpp:9-46`); it was built
  from `nM`, which leaves those out. MD now also writes an N read base on an
  N genome base as a mismatch.
- Options STAR refuses with SAM output are now refused too: `ch`, `vA`, `vG`,
  `vW`, `GX` and `GN` in `--outSAMattributes` (so `All`), and
  `--waspOutputMode SAMtag` (`Parameters_samAttributes.cpp:225-242`,
  `Parameters.cpp:882-887`). `vA`/`vG` without `--varVCFfile` and `vW` without
  `--waspOutputMode` are refused as in STAR (`:187-199`).
- **`SJ.out.tab` is filtered as STAR's `outputSJ` does** (from
  @BenjaminDEMAILLE's #316, `outputSJ.cpp:59-120`). The intron-length limit
  of `--outSJfilterIntronMaxVsReadN` was off by one and still applied above
  three reads, where STAR has none; a threshold of -1 passed everything, where STAR's
  unsigned cast lets nothing through; a junction's overhang did not end at an
  indel; and the distance filter looked at the previous junction's end rather
  than at the nearest other donor and the nearest other acceptor, with
  annotated junctions counted as neighbours but never dropped. On the yeast
  10k reads `SJ.out.tab` is now identical to STAR's, SE and PE, annotated and
  unannotated index (main kept 1 or 2 junctions STAR drops and missed 2 or 3
  it keeps). Two-pass mode inserts pass 1's `SJ.out.tab`, so its output now
  matches STAR's too.
- **`--outFilterType BySJout` works in STAR's two stages** (from #316). A read
  with an unannotated junction is held; once every read is mapped, the novel
  junctions that pass the `SJ.out.tab` filters (distance filter included) are
  collected from all reads, and the held reads are mapped again with only
  those junctions allowed (`stitchWindowAligns.cpp:169-177`) and written after
  the others. The final `SJ.out.tab` skips the distance filter, as STAR's
  second stage does. Main dropped a held read's alignments when one of its

  Alignment is 20% (SE) to 39% (PE) faster. The changes:

  - **Seeding.** Padding sorts above every base in the suffix-array binary
    search (`SuffixArrayFuns.cpp:26-53`). An `N`-flagged SAindex prefix is not
    tight (`iSA1noN`, `ReadAlign_maxMappableLength2strands.cpp:73-98`). A
    chain is searched only while more than `seedMapMin` bases remain
    (`ReadAlign_mapOneRead.cpp:65`), and the reverse pass skips its first
    start when the forward pass mapped the whole piece (`flagDirMap`). Every
    MMP that maps at most `seedMultimapNmax` times is stored, however short
    (`ReadAlign_storeAligns.cpp`).
  - **`--genomeSAsparseD` indexes are searched as STAR searches them**: each
    seed position tries `min(pieceLength, sparseD)` shifted starts and keeps
    the longest (`ReadAlign_maxMappableLength2strands.cpp`). Only one start
    was tried, so reads went unmapped or misplaced on any sparse index. Yeast
    10k against a `--genomeSAsparseD 3` index: SE 8,668 → 8,926 of 8,926 reads
    with STAR's alignment set, PE 8,165 → 8,388 of 8,388.
  - **Windows.** Seeds are assigned to windows keyed on the junction index for
    annotated-junction halves (`WA_sjA`, `ReadAlign_assignAlignToWindow.cpp`),
    with overlaps resolved in STAR's order, and a seed with the same read start
    as an existing one placed after it. Window formation handles long splices
    with the default `alignIntronMax 0`; window flanks stop at the chromosome
    boundary and overwrite earlier windows' bins, as STAR's `winBin` does
    (`ReadAlign_stitchPieces.cpp:96-111`).
  - **Stitching.** Seeds on the same diagonal are never stitched
    (`stitchAlignToTranscript.cpp:315,350`); insertions are built between
    overlapping seeds; two halves of one annotated junction are stitched
    through it without a junction scan (`stitchAlignToTranscript.cpp:18-34`);
    a short second exon no longer ends the stitch before the junction scan,
    which can give it its bases back; a non-canonical or deletion flush that
    would empty an exon is rejected (`-1000005`); stitched mismatches are
    capped by `outFilterMismatchNmax` alone (the ratio is `mappedFilter`'s);
    and the recursion is no longer cut at 100,000 calls (a 10M guard remains).
  - **Recording transcripts in a window.** STAR's paired-end
    junction-consistency walk (`stitchWindowAligns.cpp:179-219`); the
    genomic-length penalty spans the first exon's start to the last exon's
    end (`:221-225`); STAR's score gate, which records a transcript only within
    `--outFilterMultimapScoreRange` of the window's best or of its mate's best
    for the read, or always with chimeric detection on (`:232-250`); then
    STAR's window dedup in discovery order (`:260-302`). Two older non-STAR
    dedups (single-end post-finalization, paired-end covered pairs) are
    removed; with STAR's rule in the stitcher they changed nothing.
  - **Multimapper order and primary.** Alignments are written in STAR's
    `trMult` (window) order, and the primary is STAR's `trBest`: best score,
    then shorter genomic span, then the earlier window
    (`ReadAlign_multMapSelect.cpp:58-91`, `ReadAlign_stitchPieces.cpp:328-329`).
    With `--outSAMmultNmax` set, the best-scoring alignments move to the top
    and the first is primary. We sorted by score and coordinate, so `HI`
    order and the primary differed from STAR on most multimappers.
  - **Chimeric detection takes the stitcher's windows as recorded.** It re-ran
    the window dedup in score order, which could evict a transcript STAR keeps
    (the dedup is order-dependent), including a chimeric partner.

- **`genomeGenerate` peak RSS cut from ~113 GB → ~11 GB** on the human
  genome (GRCh38, 32 threads). The construction pipeline no longer
  materialises three large intermediates that were dominating the peak:

  - The ACGT-only **kept-positions `Vec<u64>`** (~47 GB on the human
    genome) — caps-sa 0.5's `build_ext_mem_for_filter` API takes a
    predicate over text positions instead, and internally maintains
    only a ~770 MB bitmap + popcount prefix sum.
  - The **spacer-free copy of `genome.sequence`** (~6.3 GB) — the new
    `dispatch_caps_sa_segmented` hands the **original** spacer-bordered

- **SAindex now parallelises across all rayon workers**. Previously
  every SAindex k-mer extraction sat on caps-sa's single-threaded
  phase-4 emit loop (~16 min of pure serial work). The new
  `SaIndex::build_parallel` reads the on-disk SA via chunked `pread`
  (so SA pages live in kernel page cache, **not** process RSS) and
  atomic-mins each k-mer's first-occurrence `sa_idx` into a
  `Vec<AtomicU64>` — the final pack into the SAindex's `PackedArray`
  is a single fast sequential pass.

- **SAindex inner loop now matches STAR's `isaStep + binary-search`
  skip algorithm** (`genomeSAindex.cpp::genomeSAindexChunk` /
  `funSAiFindNextIndex`). Consecutive SA entries share monotonically
  non-decreasing k-mer prefixes; rather than visit every entry, each
  rayon worker jumps forward by `isa_step = nSA / 4^nbases` (≈ 22 on
  human) and only stops to record k-mer boundaries — binary-searching
  inside the last `isa_step` window when `(indFull, iL4)` changes.
  Per-worker `ind0_local[il]` tracks the last-written k-mer index at
  each level so we skip writes inside a constant-prefix run; cross-
  chunk merge still uses `fetch_min` on the shared `Vec<AtomicU64>`.
  Drops the SAindex phase from ~10:50 to ~8 s on the human genome
  (~80× speedup), making rustar-aligner's full `genomeGenerate`
  **faster than upstream STAR 2.7.11b** (7:36 vs 11:26 wall, 32
  threads).

- **SAindex absent-slot encoding now matches STAR's** (`next_present
  _sa_idx | absent_mask` for between-present gaps, `n_entries
  | absent_mask` for tail-gaps). A single backward pass per SAindex
  level fills the gaps in place inside `firsts[]` before encoding
  into the output `PackedArray`. `hierarchical_lookup` is unchanged
  because it only consults the absent flag bit, not the slot's
  value; this change makes the on-disk SAindex bytes closer to
  STAR's (N flag bit is still not tracked — that's the only remaining
  divergence and a `hierarchical_lookup`-irrelevant one).

- **rayon thread pool now bound to `--runThreadN` at the
  run() dispatcher** rather than only inside `align_reads`. On a
  256-core machine this drops the rayon pool from 256 (the
  `num_cpus::get()` default) to whatever `--runThreadN` says,
  eliminating ~15 GB of glibc-arena-style allocator slack from
  256 worker-thread heaps.

- **mimalloc as the global allocator**. Lower per-allocation cost than
  glibc's malloc and per-thread heaps that return whole segments to
  the OS when abandoned, so allocator cache size stays bounded.

- **`--soloCellReadStats CB`** writes `Solo.out/<feature>/CellReads.stats`:
  one row per cell barcode with fifteen counters describing what
  happened to its reads — barcode match quality, unique or multi
  genomic mapping, feature assignment, exonic/intronic and their
  antisense counterparts, mitochondrial, and whether the read reached
  the matrix — plus the per-cell UMI and gene totals. Reads whose
  barcode never resolved are summed into a `CBnotInPasslist` row rather
  than dropped, so the columns account for the whole input.
  `--genomeChrSetMitochondrial` names the chromosomes behind the `mito`
  column.
- **`--runMode soloCellFiltering <raw dir> <output prefix>`** cell-calls
  an existing raw count matrix without aligning anything. Cell calling
  is a decision about a matrix, not about reads: re-calling with
  different `--soloCellFilter` parameters should not mean re-aligning,
  and a matrix produced elsewhere should be callable too. It streams
  the matrix into the same form the align path produces, so the filters
  are the identical code rather than a second implementation.
- **`--soloCellFilter EmptyDrops_CR` now uses CellRanger's actual
  statistics.** The ambient profile is smoothed with Simple Good-Turing,
  as CellRanger and STAR do, instead of an approximation that reserved
  unseen mass from the singleton rate and spread the remainder in
  proportion to raw counts. The Monte-Carlo null is drawn with libc++'s
  `std::mt19937` and `std::discrete_distribution`, seeded
  `19760110 * (isim + 1)` per simulation as STAR seeds it, replacing a
  SplitMix64 stream that could not agree with STAR's over an arbitrary
  number of draws. Cell calls move as a result.

- **`--soloFeatures Transcript3p`** quantifies transcripts rather than
  genes, using how far each read's 3' end sits from each transcript's.
  In a 3'-biased assay that distance discriminates between isoforms: a
  read 200 bases from the end of one and 4000 from the end of another
  is evidence for the first. The distance distribution is estimated
  from the data, then used as the likelihood in an EM over UMIs. Output
  is per *cluster* rather than per cell — `--soloClusterCBfile` (new,
  and required for this feature) says which cell is in which cluster,
  because one cell has too few UMIs to resolve isoforms. Reads sharing
  a UMI contribute the intersection of their transcript sets, not the
  union: they came from one molecule. Writes `matrix.mtx`,
  `features.tsv` and `transcriptEndDistanceDistribution.txt` under
  `Solo.out/Transcript3p/raw/`.
- **Chimeric multimapping detection (`--chimMultimapNmax`)**, STAR's
  newer enumeration path. Instead of pinning the best transcript and
  looking for one partner, it walks every transcript pair, keeps those
  within `--chimMultimapScoreRange` of the best chimeric score, and
  reports them all. A read whose fusion partner maps equally well to two
  places yields two junctions rather than an arbitrary one.
  `--chimNonchimScoreDropMin` gates the search on the linear alignment
  leaving enough of the read unexplained, and a read with more surviving
  loci than the cap reports none at all, as STAR does. The default of 0
  keeps the old single-best path.

- **`--chimFilter banGenomicN`** (STAR's default) drops a chimeric
  junction whose flanking genomic bases are not real bases: sequence
  around an assembly gap yields junctions that look clean by score and
  mean nothing. `--chimFilter None` keeps everything.

  highest read count; CellRanger gives a tied UMI to no gene at all.
  Since one read per gene is the ordinary shape of a multi-gene UMI, the
  flag removed nothing in practice. On a 20k-read 10x fixture the count
  matrix moves from 16 465 to 15 414 against STAR's 15 423.
- `--soloUMIfiltering MultiGeneUMI_All` was aliased to `MultiGeneUMI`,
  which is neither STAR's behaviour nor the documented one: in STAR
  2.7.11b the variant is a no-op. It now removes a UMI seen in two or
  more genes from **all** of them, the behaviour the option name
  describes. Recorded in `DIVERGENCE.md` (closes #144).
- The STARsolo adapter search took the leftmost match inside the
  mismatch budget; STAR's `localAlignHammingDist` takes the
  best-scoring one. Since `CB_UMI_Complex` measures barcode positions
  from the adapter, the wrong offset shifted the whole barcode. Ties now
  go to the leftmost of the best, and an `N` in the adapter is a
  wildcard rather than a mismatch.

- **STARsolo `Gene` assignment now requires exon concordance**, matching
  STARsolo: a read counts toward a gene only when every aligned block
  lies within the gene's exons, rather than merely overlapping one. This
  removes over-assignment of reads that extend past an exon boundary into
  an intron. On the mouse-chr19 differential test the `Gene` count matrix
  now matches STAR 2.7.11b (raw matrix identical apart from the
  multimapper tie-break tail that even a byte-faithful reimplementation
  cannot reproduce).
- **STARsolo `features.tsv` column 2 now emits the GTF `gene_name`**
  (symbol), with the STAR gene_id fallback, instead of duplicating the
  gene_id.
- **`--outSAMtype BAM SortedByCoordinate` no longer buffers the whole
  output in RAM.** The coordinate sort is now external: it fills a
  `--limitBAMsortRAM` buffer, spills sorted runs beside the output, and
  k-way merges them on finish. Peak memory is flat in output size
  (measured: 610 MB at a 64 MiB budget for 300 k through 2.4 M records,
  versus 648 MB → 2,132 MB before, a growth of 723 B/record that
  extrapolated to ~116 GB for a 160 M-record human sample). Output is
  byte-identical to the previous in-memory sort — coordinate ties still
  resolve to input order, since runs merge with the run index as
  tiebreak (verified at 2.4 M records through a 219-run multi-pass
  merge). `--limitBAMsortRAM N` now spills above `N` rather than
  aborting the run, and `--limitBAMsortRAM 0` means 512 MiB instead of
  "unlimited". Runs beyond 64 are merged in balanced passes so a small
  budget on a large run cannot exhaust file descriptors. Spill runs go to
  `--outTmpDir` when given (previously accepted and ignored), otherwise beside
  the output, and are always removed. See DIVERGENCE.md §4.3.

### Bumps

- `caps-sa` → `0.5` (adds `build_ext_mem_for_filter*`; see the caps-sa
  v0.5.0 release notes).

### Other

- New module `index::packed_stream` — bit-for-bit-compatible streaming
  writer for STAR's `PackedArray` format. Used by the streaming SA
  emit; documented to match `PackedArray::write` for `word_length ≤ 57`
  (the upper bound where the existing `PackedArray::write` is
  truncation-free; STAR's production widths are 32-37).

- New module-level `GenomeIndex::generate_streaming(params)` — the
  full `genomeGenerate` pipeline, used by the `genomeGenerate`
  run-mode dispatcher. The in-memory `GenomeIndex::build` +
  `GenomeIndex::write` flow remains for tests and any caller that
  needs random access to the SA in RAM.

- Removed `Transcript::read_seq`, a public field that was filled with a
  copy of the read at every finalised alignment and never read. **API
  removal.** Output is unchanged.

- The splice-motif check in the junction scan carries a sliding window
  and looks the motif up in a table, instead of re-reading four genome
  bases and matching on them at every position. Consecutive junction
  positions share two of the four bases, so the scan does two genome
  reads per position rather than four. Output is unchanged (SAM
  byte-identical on 200k reads); about 2.8% off the wall clock on a
  2M-read run, measured with `test/bench_ab.sh`.
